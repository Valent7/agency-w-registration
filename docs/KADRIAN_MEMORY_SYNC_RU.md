# Как синхронизировать память Kadrian и облака

**Сейчас это инструкция к подготовленному коду PR №85. Он ещё не установлен.**
Кнопки новой памяти появятся только после отдельного разрешения владельца,
установки и включения для одного выбранного проекта. Этот документ не является
разрешением на установку. Рабочие настройки при его подготовке не менялись.

## Самое важное

Локальная папка и облако пока **не обмениваются изменениями сами**. Работает
контролируемый обмен файлами: сверить проект и версию → просмотреть изменения →
импортировать. Загрузить пакет — не то же самое, что утвердить новое общее правило.

Обычные технические действия может выполнять Кадриан в Codex. Владельцу не нужно
вручную редактировать JSON или передавать серверные ключи. Владелец выбирает
проект, проверяет состав передаваемых сведений и утверждает изменения общих правил.

## Что автоматизировано, а что пока вручную

Здесь «автоматизировано» означает **реализовано и проверено в подготовленном коде**,
а не «уже работает в действующем Агентстве».

| Действие | Сейчас в подготовленной версии |
|---|---|
| Сохранить переписку и события выполнения в выбранном проекте | Автоматически при работе облачного чата/исполнителя |
| Зафиксировать возможное замечание или решение из сообщения | Автоматически, по простым признакам текста; запись предварительная, возможны пропуски классификации |
| Прочитать утверждённые правила перед новой задачей | Автоматически, только в выбранном проекте |
| Повторить доставку событий после сбоя без дубликатов | Автоматически при следующей сверке/проходе; исходная история сохраняется |
| Найти владельца, агента и проект пакета, проверить контрольную сумму | Автоматически при импорте |
| Проверить, не изменилась ли версия облака/локальная проекция | Автоматически; при конфликте обновление останавливается |
| Составить пакет из четырёх локальных файлов | Кадриан/специалист запускает готовую функцию вручную, при поручении на синхронизацию |
| Скачать облачный пакет и загрузить локальный | Вручную через кнопки кабинета; фонового обмена нет |
| Сверить смысл различий и решить, как разрешить конфликт | Владелец с помощью Кадриана; автоматического слияния по смыслу нет |
| Обновить локальную проекцию облачной памяти | Кадриан запускает функцию после сверки; резервная копия и замена файла выполняются автоматически |
| Перенести старые заметки и переписку в новую память | Первый запуск вручную кнопкой; оригиналы не удаляются |
| Проверить качество результата и утвердить общее правило | Явные действия доверенного проверяющего и владельца; агент сам правило не утверждает |
| Скачать зашифрованную резервную копию | Вручную; шифрование и проверка целостности автоматические |
| Создавать внешние резервные копии по расписанию | Пока не настроено |
| Следить за локальными файлами, когда компьютер выключен | Не реализовано и невозможно без работающего локального процесса; облако использует последнюю загруженную версию |

## Перед первой синхронизацией

Эти действия выполняются **после отдельного разрешения на установку**, не сейчас.

1. Владелец выбирает один проект для пилота. Используется его постоянный UUID,
   а не название: у двух проектов могут быть одинаковые названия.
2. Специалист после разрешённой установки задаёт одновременно:
   `AGENCY_MEMORY_V1=1`, разрешённого владельца в `AGENCY_MEMORY_V1_OWNERS` и
   **один** UUID в `AGENCY_MEMORY_V1_PROJECT_ID`. Значения выбранного проекта в web
   и worker должны совпадать; перед запуском это проверяется отдельно. Списки
   проектов, `*`, пустые и неверные значения не включают новую память.
3. В кабинете выбранного проекта появляется раздел
   **«Версионная память и проверенные правила»**. В остальных проектах его нет;
   они продолжают пользоваться старой памятью.
4. Для обычной синхронизации выберите область **«Только этот проект»**.
   Области общих правил — отдельная процедура утверждения, не место для клиентской истории.
5. При необходимости один раз нажмите
   **«Перенести старые заметки и переписку без удаления оригиналов»**.
   Это не делает старые записи автоматически проверенными правилами.

Никому не нужно присылать SUPABASE_SECRET_KEY, ключ шифрования или ключи моделей.

## Из локальной папки Kadrian в облако

1. В выбранном облачном проекте откройте новую память, область
   **«Только этот проект»**, и нажмите
   **«Скачать версию для локальной сверки (данные проекта)»**.
   Сохраните пакет в приватной папке `Kadrian/.memory-exchange/`.
2. Поручите Кадриану в Codex:
   «Сверь этот облачный пакет с локальной памятью выбранного проекта и подготовь
   пакет обновления. Покажи, какие сведения уйдут в облако».
3. Кадриан проверяет известные идентификаторы владельца/проекта и пакет, берёт из
   него базовый номер версии и собирает **другой, локальный пакет** через
   `agent_memory_sync.local_bundle`. В него входят только:
   - `Agent.md`;
   - `context/PROJECT.md`;
   - `context/DECISIONS.md`;
   - `context/FEEDBACK.md`.
4. Просмотрите состав. Не включайте ключи, пароли, переписки другого клиента и
   посторонние материалы. Если файлы относятся к разным клиентам, сначала
   разделите контекст; не загружайте смешанную папку в один проект.
5. В том же разделе кабинета выберите получившийся локальный JSON в поле
   **«Контролируемый импорт: локальный JSON или зашифрованная резервная копия»**.
   Кабинет покажет область, базовую/текущую версии и содержимое файлов.
6. После проверки отметьте **«Проверила область и разрешаю импорт в выбранную память»**
   и нажмите **«Импортировать»**.
7. При успехе номер версии увеличится; локальные файлы сохранятся как запись
   `legacy` с достоверностью `unknown`. Их текст доступен как контекст, но не
   становится новыми системными инструкциями. Повтор того же пакета не создаёт
   дубликат. Скачайте новую версию для следующей сверки.

**Важно:** файл, скачанный из облака, имеет формат `agency-memory/1`. Локальный
пакет на загрузку — `agency-local/1`. Это не один и тот же файл. Нельзя просто
загрузить облачный экспорт обратно как локальное обновление.

`AGENTS.md`, `.env`, секреты, видео, музыка и каталоги других клиентов не попадают
в пакет этой функцией. `context/SYNCED_MEMORY.md` тоже не отправляется обратно:
это защищает от бесконечного копирования облачной проекции в саму себя.

## Из облака в локальную папку Kadrian

1. В том же проекте и той же области скачайте актуальную версию кнопкой
   **«Скачать версию для локальной сверки (данные проекта)»**.
2. Поручите Кадриану: «Проверь владельца, проект и целостность пакета. Покажи отличия
   от текущей локальной проекции и обнови её после сверки».
3. Кадриан проверяет пакет и применяет `apply_reviewed_projection`, передав
   контрольную сумму именно просмотренного пакета и текущего локального файла.
4. Результат появляется в **`context/SYNCED_MEMORY.md`**. Предыдущая версия этого
   файла сохраняется в **`.memory-backups/`**; смена файла атомарная. Если между
   сверкой и записью кто-то изменил файл, операция остановится.
5. `AGENTS.md`, `Agent.md`, `PROJECT.md`, `DECISIONS.md`, `FEEDBACK.md` не
   перезаписываются. Импортированная проекция — данные с отметками достоверности
   и статуса. Она не даёт новых прав на инструменты и не меняет общие инструкции.
6. При следующей работе в Codex нужно прочитать `Agent.md` и относящиеся к задаче
   файлы `context/`, включая эту проекцию. Сам файл не гарантирует чтение: это
   обязанность процесса работы агента, а не фоновая функция синхронизации.

Для переноса изменений из облака именно в основные локальные журналы пока нужна
отдельная смысловая сверка Кадрианом. Автоматической двусторонней перезаписи этих
Markdown-файлов нет.

## Если возник конфликт

- **Облако изменилось после скачивания.** Старый пакет не импортируется. Скачать
  актуальную версию, сравнить оба изменения и подготовить пакет с новой базовой
  версией. Не подменять номер версии вручную, чтобы «протолкнуть» старое содержимое.
- **Локальная проекция изменилась.** Сохранить оба варианта, заново просмотреть
  отличия и только затем обновить её. Прежняя версия остаётся в резервной папке.
- **Другой владелец/проект, повреждённый пакет, недопустимые файлы.** Остановиться,
  проверить исходный пакет и выбранную область. Не отключать проверки.
- **Слишком большой пакет.** Кабинет ограничивает загрузку 4 МБ, документ памяти —
  2 МБ. Потребуется план архивирования/отдельного переноса; обход лимитов не предусмотрен.
- **Раздел новой памяти отсутствует.** Проверить, что это выбранный пилотный проект
  и функция установлена и включена после разрешения. Не включать её сразу всем.

## Резервная копия и откат

**«Резервная копия памяти (зашифрована)»** — отдельная кнопка. Она использует уже
настроенный ключ шифрования сервера; ключ не скачивается. Это архив `.enc` для
восстановления, а не обычный локальный пакет синхронизации. На сервере без
существующего ключа кнопка не предлагается.

Восстановление разрешено только в пустое совпадающее рабочее пространство либо
для продолжения того же прерванного восстановления. Восстановленные правила
требуют нового утверждения; история заданий не запускается заново. Не очищать
работающую память ради загрузки архива.

Чтобы остановить пилот после отдельного решения владельца, специалист отключает
функцию или убирает выбранный UUID из конфигурации обоих процессов. Новая история,
задачи и незавершённые записи не удаляются; остаётся прежняя система. Возврат
прошлого правила делается отдельной версией, а не восстановлением всей старой БД.

## Приватность и оплата

`.memory-exchange/`, `.memory-backups/`, `*.agent-memory.json` и проекция не должны
попадать в GitHub, публичные чаты или общий диск. Выгрузка для сверки содержит
данные проекта открытым текстом; хранить её в приватной папке владельца. Для
долгосрочного архива использовать зашифрованную копию. Нового платного сервиса
или вызова модели для этой синхронизации не требуется. Используются текущие
хранилище и сервер; их квоты могут расходоваться при росте истории.

## Техническое приложение для Кадриана/специалиста

Команды ниже — **локальные функции**, без сетевых запросов и без установки схемы.
Выполняются из копии кода ветки PR №85 после сверки пакета. Пути и идентификаторы
задаются специалистом из доверенной конфигурации выбранного проекта, а не
принимаются на веру из загруженного файла. Сам владелец этот код вводить не обязан.

Подготовка локального пакета после скачивания облачной версии:

```python
import json
from pathlib import Path
from agent_memory import Scope, validate_bundle
from agent_memory_sync import local_bundle

# Эти значения подставляет Кадриан из проверенных данных выбранного проекта.
root = Path(KADRIAN_ROOT)
scope = Scope(OWNER_ID, "kadrian", PROJECT_ID, PROJECT_ID)
cloud = json.loads(Path(DOWNLOADED_CLOUD_FILE).read_text(encoding="utf-8"))
validate_bundle(cloud, scope)
base = cloud["revisions"][-1]["revision"] if cloud["revisions"] else 0
package = local_bundle(root, scope, base)
# Сначала показать package["files"] владельцу; сохранять приватно, не в Git.
out = root / ".memory-exchange" / "kadrian-upload.agent-memory.json"
out.parent.mkdir(mode=0o700, exist_ok=True)
import os
fd = os.open(out, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, "w", encoding="utf-8") as stream:
    json.dump(package, stream, ensure_ascii=False, indent=2)
# Если такое имя уже существует, выбрать новое; не перезаписывать без сверки.
```

Обновление локальной проекции из уже просмотренного облачного пакета:

```python
from agent_memory import digest
from agent_memory_sync import apply_reviewed_projection

projection = root / "context" / "SYNCED_MEMORY.md"
# Эти два значения фиксируются в момент просмотра и не пересчитываются для обхода конфликта.
reviewed_checksum = cloud["checksum"]
reviewed_local_hash = digest(projection.read_text(encoding="utf-8") if projection.exists() else None)
# Здесь просмотреть отличия; затем применить ровно тот же пакет и те же значения.
apply_reviewed_projection(root, cloud, scope,
                          expected_checksum=reviewed_checksum,
                          expected_local_hash=reviewed_local_hash)
```

При ошибке сверки оригиналы остаются на месте. Техническая проверка пакета не
заменяет смысловой проверки сведений и утверждения общих правил владельцем.
