# Instagram для партнёров — запуск без Facebook Developer (15.10.2026)

## Цель и текущий статус

**Одна кнопка в кабинете Агентства W:** владелец профессионального Instagram
аккаунта даёт разрешение приложению `Agency W-IG`, после чего Неона может
работать в Direct и с комментариями по действующим разрешениям. Партнёр
**не должен** становиться разработчиком Facebook, получать доступ к Render,
GitHub, Supabase, App Secret или чужим данным.

- Основное приложение Meta: **Agency W** (публичный ID `1101869308929738`).
- Instagram Login client: **Agency W-IG** (публичный ID `2153768211848484`).
- Instagram API with Instagram Login — **без обязательной связи с Facebook Page**.
- Запрашиваемые scopes: `instagram_business_basic`,
  `instagram_business_manage_messages`, `instagram_business_manage_comments`.
- Скриншоты Meta показывают **«Готово к тестированию»**, а не одобренный
  доступ к аккаунтам любых сторонних пользователей. Процедура App Review
  (шаг 5) не завершена.
- Администраторский Instagram `@ai_v_ton` ранее успешно отправлял ответы
  Неоны через Direct (подтверждено боевым webhook/логами). Это **не доказывает**
  работоспособность для произвольных сторонних аккаунтов.
- Попытки новых партнёров получить долговременный токен отклонялись:
  `IGApiException code 100 / Unsupported request method type get`, затем
  `post`. Причина **не доказана**, но ограничения тестовых ролей/непроверенные
  права Meta — проверяемый блокер. Используем документированный GET; нельзя
  заменять App Review бесконечными повторами запроса.
- Агентство пока разрабатывается **без официальной регистрации бизнеса**;
  нельзя вводить вымышленные юридические данные или обещать одобрение Meta.

## Что готово в коде

1. Подключение через /instagram/connect → Instagram OAuth → callback в
   Render. Состояние OAuth подписывается и проверяется; секреты хранятся
   только на сервере.
2. Краткосрочный токен обменивается на долгосрочный, аккаунт идентифицируется
   по native `user_id`, привязка владельца изолирована, подписка на webhook
   выполняется после подключения.
3. Meta webhook с неверной подписью отклоняется; приватные сообщения не
   записываются целиком в технические логи.
4. Подключение **не помечается успешным**, если токен не выдан. При отказе Meta
   пользователь видит понятную причину и ссылку возврата в кабинет.
5. Зелёная карточка подтверждает сохранённую авторизацию, **не** работу Direct
   без живой проверки.

## Что не позволяет массовый запуск прямо сейчас

**Официальный доступ Meta** для сторонних профессиональных аккаунтов.
Опубликованный режим приложения сам по себе не равен одобрению расширенных
разрешений. Присвоение тестовой роли — временный путь для доверенных
участников, не замена App Review и не требование к платным клиентам.

По экрану Meta для запроса проверки может потребоваться статус
**Tech Provider**, подтверждение бизнеса и/или прав доступа. Условия
зависят от действующей процедуры Meta; окончательное решение принимает Meta.

## Подготовка к App Review (действия владельца)

1. В Meta Developers открыть Agency W → Instagram API → Permissions and
   Features; запросить нужные разрешения на проверку только после подготовки
   доказательств работы. Не запрашивать лишние scopes.
2. Проверить в Meta Business Portfolio статус бизнес-аккаунта и требований
   к Tech Provider / Business Verification. Не отправлять неподтверждённые
   сведения о регистрации.
3. Привести в соответствие с реальной обработкой данных опубликованные
   Privacy Policy, Terms, инструкцию удаления данных, контакт и права
   субъектов данных. Для Германии также проверить GDPR/DSGVO, цели и сроки
   хранения, обработчиков данных, получение согласия в нужных сценариях.
4. Записать **демонстрационное видео** для каждого запрошенного разрешения:
   вход тестового профессионального Instagram-аккаунта с явным согласием,
   привязка к правильному владельцу, входящий Direct → ответ Неоны; отдельная
   демонстрация обработки комментария и утверждения/отправки ответа.
   Использовать контролируемые тестовые аккаунты и скрывать реальные чаты.
5. Подготовить тестовые шаги для модератора Meta, рабочие URL, точные
   обоснования использования каждого permission и необходимый доступ для
   проверки без реальных личных сообщений.
6. После одобрения провести пилот на независимом профессиональном
   Instagram-аккаунте **без app role**. Подтвердить выдачу токена, запись
   native ID, подписку на webhook, входящий Direct, отправленный ответ,
   отсутствие дублирования и межвладельческих утечек.
7. Только после пилота обозначать «Instagram доступен всем партнёрам».

## Критерии приёмки

- Пользователь без Facebook Developer может открыть кабинет Agency W и
  начать Instagram Login.
- При отказе Meta система **не врёт об успешном подключении** и даёт
  понятный следующий шаг.
- После реального одобрения сторонняя учётная запись Instagram подключается
  без назначения ей app role.
- На входящий тестовый Direct есть один своевременный ответ от имени
  правильного владельца; чужие учётные данные не используются.
- Если отправка невозможна, сохраняется корректный технический статус,
  а пользователь получает понятную информацию без раскрытия токенов.
- Нет обещаний о гарантированной скорости, доступности и одобрении Meta;
  измеряем результат по реальным логам.

## Чего НЕ делать

- Не передавать партнёрам App Secret, токены, доступ администратора Meta,
  Render, Supabase или GitHub.
- Не подключать «обходные» неофициальные Instagram API, сбор паролей,
  cookies или чужих сессий для имитации официального OAuth.
- Не сохранять короткосрочный токен в виде полноценной 60-дневной связи,
  если выдача долгосрочного не подтверждена.
- Не предлагать клиенту массово создавать Facebook Developer аккаунты.
- Не использовать реальные сообщения людей для App Review без разрешения.
