# Профессиональная память Разведчика в кабинете

Подключение подготовлено поверх PR №94 и №96. Кнопка «Провести разведку» использует прежний путь, пока серверный переключатель выключен. Настройки задаются только на сервере.

| Переменная | Назначение |
|---|---|
| `SCOUT_MEMORY_ENABLED` | По умолчанию выключено. Значение `1` разрешает подключение для согласованного владельца. |
| `SCOUT_MEMORY_OWNER_ID` | Telegram ID владельца, совпадающий с аутентифицированным владельцем кабинета. |
| `SCOUT_MEMORY_PROJECT_ID` | UUID согласованного проекта Разведчика в существующей памяти Agency W. |
| `SCOUT_MEMORY_WORKSPACE` | Абсолютный путь к закрытой серверной копии профессиональной рабочей папки Разведчика за пределами checkout. |

Перед включением сверить владельца и UUID проекта. Подготовить серверную копию рабочих материалов из папки «Агентство W → Разведчик». Копировать только файлы из `agent_workspaces.FILES` и `.agent-profile.json`. Локальные результаты тестов и локальная привязка не переносятся. Каталог должен принадлежать пользователю приложения, допускать создание серверной привязки и быть доступным после перезапуска. Проверить существующее хранилище Agency W и права в тестовом окружении. Код не создаёт таблиц или отдельного хранилища.

При запуске `AgentWorkspace.begin` проверяет доступ, загружает инструкции и подтверждённый опыт. Отчёт и ссылки сохраняются в существующем Repository. Новый запуск получает свой идентификатор. Повтор того же завершённого задания с прежним идентификатором возвращает сохранённый результат. После перезапуска отчёты и форма обратной связи доступны из истории проекта. Старая история остаётся доступной отдельно.

Директор может сохранить замечание или добавить проверенное исправление. Для исправления форма требует источник и явное подтверждение проверки. Повтор той же формы использует тот же идентификатор события. Проверка привязана к хешу исправления. Общие правила проходят существующий процесс утверждения.

Для отключения установить `SCOUT_MEMORY_ENABLED=0` на сервере. Кнопка вернётся к обычному исследованию, а накопленные записи останутся в хранилище и снова появятся после включения той же привязки. Если включённая память недоступна, кабинет останавливает исследование до запроса модели.

Синтетические проверки используют локальное хранилище и имитацию модели. Развёртывание, рабочая привязка, активация, перенос прежних записей и платное исследование требуют отдельного поручения директора.
