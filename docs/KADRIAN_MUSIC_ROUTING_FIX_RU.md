# Музыка, монтаж и остановка Кадриана

Изолированное исправление от main, без кода PR №85 (память) и №86 (отдельные фильмы).

## Поведение

- «Подключи музыку», «Где музыка?», «Наложи вторую музыку» обрабатываются до модели:
  они не могут превратиться в новый заказ Runway. Если музыка/сцены недоступны,
  показывается конкретная причина без автоматической генерации исходников.
- В «Монтаж готовых сцен и ваша музыка» можно выбрать фрагменты в нужном порядке,
  прослушать сохранённый трек и собрать готовое видео. Сборка выполняется FFmpeg
  на существующем web-сервере, не обращается к платным генераторам, работает
  даже при приостановленном фоновом worker. Отдельная стоимость API-монтажа отсутствует;
  используются существующие CPU, база и файловое хранилище с их обычными тарифами.
- Музыка из чата сохраняется независимо от сценария и текста запроса. Пустой MIME
  MP3 нормализуется; файл проверяется ffprobe. Выбор и порядок прикрепления
  переживают перезапуск. Если указана вторая музыка, первая не подставляется
  при её отсутствии. Неподдерживаемый новый трек не заменяется прежним.
- Если в старом открытом окне остался прикреплённый MP3, он сохраняется при первом
  открытии новой версии. Если окно/сервер уже потеряли несохранённый файл, его
  нельзя восстановить из текста: потребуется прикрепление исходника заново.
- «Стоп» и кнопка «Остановить создание сцен» ставят запрет новым видеозаказам
  выбранного проекта и приостанавливают ожидающие/обрабатываемые задания студии.
  Задания других владельцев/проектов и обычные задания вне Кадриана не меняются.
- Уже принятый внешним видеосервисом запрос может закончиться, его списание
  остановкой не отменяется. Идентификаторы поставщика, файлы и контрольные точки
  сохраняются. Остановка не означает удаление результата или возврат кредитов.
- Старое сообщение «Создаю сцену» показывается как история, статус берётся из
  текущей записи. Локальный монтаж появляется в готовых работах.

## Технические границы

`kadrian_editing.py` содержит проверку намерения, сохранение/выбор музыки,
остановку и идемпотентную сборку. `kadrian_editing_ui.py` — выбор готовых исходников,
прослушивание и кнопки. `kadrian_actions.py` имеет дополнительный запрет видеозапуска
на границе очереди. `kadrian_studio_ui.py` выполняет команду музыки/стоп до модели,
рисования и маршрута Runway. Текстовая остановка обрабатывается даже до проверки
новых вложений. Для голосовой команды нужен существующий этап распознавания.

`pause_studio_job` в SQLiteStore/SupabaseStore — отдельная операция владельца:
проверяет owner/project/job/revision/studio/state и атомарно снимает рабочую аренду.
Общий `update_job` не ослаблен. Worker проверяет паузу проекта перед контрольными
точками; потерянная аренда не позволяет старому процессу записать новый этап.
Между последней проверкой и уже отправляемым запросом поставщику возможна гонка;
поэтому отмена принятого внешнего заказа/возврат средств не обещаются.

Производственная пауза сохраняется в `kadrian_production_paused`. Она не снимается
автоматически, старые задания не возвращаются в очередь. Для последующего
разрешения новых сцен оператор должен отдельно проверить очередь и снять флаг;
эта операция не включена в текущий пользовательский монтаж. Render worker также
не возобновляется автоматически.

Сборка: 1–12 готовых H.264 фрагментов одного размера/частоты/временной базы,
до 10 минут и 100 МБ итогового MP4. Картинка копируется без изменения скорости;
музыка берётся с начала, не зацикливается, не растягивается, плавно завершается.
Существующая речь не удаляется молча: при наличии звука в исходном видео замена
останавливается, пока владелец явно не выберет «Заменить весь прежний звук, включая речь».
Разные форматы/нечитаемые файлы дают ошибку, а не заказ новой генерации.
Один и тот же набор сцен/музыки возвращает уже готовый результат. Конкурирующие
сборки защищены существующей арендой. Ошибка не удаляет исходники.

Сохранение использует существующий JSON проектов/заданий и частное хранилище.
SQL-миграции, новые сервисы, ключи и изменение общих инструкций не требуются.
В main пока нет отдельных фильмов: это остаётся предметом PR №86; исправление
не заявляет изоляцию фильмов, которой действующая версия ещё не имеет.

## Проверки и установка

```sh
python -m unittest tests.test_kadrian_editing -v
python -m unittest discover -s tests -p 'test_kadrian*.py' -v
python -m unittest discover -s tests -v
```

Тесты используют временную SQLite и подменённых провайдеров. Реальный медиатест
в Linux создаёт красный/синий клипы и звуковой тон локальным FFmpeg: проверяет
порядок, 48 кадров, 2 секунды, аудиодорожку. Генерации поставщиков не нужны.
Контракт Supabase проверяется через подмену HTTP, без рабочей базы.

Перед установкой: проверить CI, сохранить копию текущих проектных настроек,
состояние очереди и рабочий commit. Worker держать на паузе. Не включать PR №85/86
попутно. После web-установки проверить, что команды музыки дают монтаж/понятную
ошибку, а не новые queued-видеозаказы. Для проверки не заказывать платные сцены.

Откат: вернуть предыдущий web commit, сохранив новые музыкальные файлы/выбор и
готовые монтажи. Старый код не знает нового запрета проекта, поэтому Render worker
оставить приостановленным, пока ошибка маршрутизации не устранена. Снятие паузы
без проверки очереди может запустить прежние ошибочные заявки.
