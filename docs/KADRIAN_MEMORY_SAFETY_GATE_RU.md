# Безопасное включение и остановка памяти — подготовка, не установка

Рабочую заглушку версии 3 не заменять до отдельного разрешения. Эта ветка
продолжает PR91 и не требует слияния в main или выпуска служб Render.

## Что изменено

1. `index.ts` больше не читает KADRIAN_MEMSYNC_CONFIG/флаги enabled из окружения.
   Публичная привязка проекта, устройства, ключа и выпуска находится в отдельном
   проверяемом binding.ts. В исходниках binding=null: закрыто независимо от env.
   Даже заполненная привязка сама по себе не включает обмен.
2. Добавляется отдельная служебная таблица выключателя в закрытой схеме
   kadrian_sync_control — без текстов памяти, событий или второй базы знаний.
   По умолчанию нет регистрации и разрешения. Единственная разрешённая память
   остаётся в существующих таблицах PR85.
3. Все чтения/записи нового обработчика проходят только через guarded RPC.
   Каждый запрос проверяет точный owner/agent/project/device/release, разрешение,
   срок и поколение. Кэша разрешения нет. Старые прямые адаптеры остаются для
   обратной совместимости тестов, но новый index их не импортирует.
4. Разрешение меняет только авторизованный оператор базы по утверждению владельца.
   Runtime не может изменять таблицу выключателя, даже своим серверным ключом.
   Mac вообще не получает серверных ключей. RPC SECURITY DEFINER нужен для SHARE
   блокировки без выдачи runtime UPDATE. Он имеет фиксированный search_path,
   явную привязку области, не меняет разрешение; PUBLIC/anon/authenticated закрыты.
5. Каждая операция держит SHARE блокировку до commit. Остановка берёт конфликтующую
   блокировку, выключает доступ и увеличивает поколение. После подтверждённого
   COMMIT остановки старое поколение уже не может записать новую ревизию.
   Начатые до остановки транзакции могут закончиться ПЕРЕД этим COMMIT;
   уже отправленный сетевой ответ нельзя отозвать. Это не обещание нулевой задержки.
   lock_timeout=3s/statement_timeout=5s: ошибка/таймаут означает, что остановка
   НЕ подтверждена, а не ложное сообщение об успехе. Запасной путь — 503-заглушка.
6. На Mac новый agent_memory_run.py требует отдельный закрытый run-permit.json,
   привязанный к хешу конфигурации/устройству/области. Файл STOPPED перекрывает даже
   сохранённое разрешение. Проверка повторяется перед каждой сетевой отправкой.
   Остановка и перезапуск процесса не стирают очередь и не регистрируют устройство заново.

## Точный порядок следующего ограниченного включения

Все действия ниже пока ТОЛЬКО ПОДГОТОВЛЕНЫ. Они потребуют разрешения на изменение
рабочей Supabase и затем отдельного разрешения на постоянный запуск.

1. Перечитать рабочую память: сейчас 38 ревизий. Сверить все хеши с сохранённым
   экспортом, сохранить свежие облачную/локальную копии, очередь/config/status,
   получить точные версии обеих Edge Functions. Проверить отсутствие отправителей.
2. Зафиксировать SHA проверенной ветки. tools/memory_edge_release.py build/verify
   создаёт неизменяемый артефакт. tools/memory_gate_binding.py создаёт ОТДЕЛЬНЫЙ
   производный пакет с public registration существующего Mac; новый release_id
   уникален, endpoint закреплён за рабочим project_ref. В GitHub клиентских данных нет.
3. Авторизованный оператор проверяет и вручную применяет ТОЛЬКО safety-gate.sql.
   Скрипт добавляет служебную схему/таблицу и одну RPC, не меняет существующую память,
   agent_memory_commit, другие функции, Render или RLS существующих таблиц.
   Проверить отсутствие прав runtime на таблицу управления и закрытие публичных ролей.
4. Инструмент memory_gate_operator.py register генерирует SQL регистрации одного
   владельца/Кадриана/проекта/Mac/release. Регистрация остаётся disabled.
   При конфликте существующей регистрации остановиться, не применять upsert.
5. Установить ТОЛЬКО проверенный пакет kadrian-memory-sync. Убедиться, что без
   активной DB-записи даже корректно подписанный запрос отвергается. Env не трогать.
6. По отдельному утверждению ограниченного испытания: memory_gate_operator.py enable
   с точным текущим generation и ссылкой на утверждение. Без --permanent разрешение
   живёт только 15 минут. Неверное поколение не включает канал. На Mac — только
   разовый запуск; launchd/hooks по-прежнему не устанавливать.
7. Выполнить живую передачу, повтор события, потерю ответа; сравнить ревизии/хеши.
   Выполнить stop и проверить отказ уже открытой сессии и новой подписанной записи.
   Подтвердить COMMIT выключателя и неизменное число ревизий после него.
   Для восстановления — новая явная enable с НОВЫМ generation; старый SQL не годится.
8. Остановиться с disabled, целой очередью/историей и отчётом реального испытания.

## Постоянный запуск — только после отдельного разрешения

Подготовить assets через prepare_gated_existing: он использует прежние config,
Keychain device и transport.enc; ничего не загружает в launchd и не меняет hooks.
В проверенном выпуске установить обновлённые Mac-модули, сохранив прежний выпуск.
Создать run-permit.json по формату agent_memory_run.permitted с точным хешем
config/device/scope и ссылкой на утверждение владельца; права 0600, каталог 0700.
После аварийного STOPPED проверить очередь и новую регистрацию поколения;
только после нового утверждения удалить STOPPED с fsync каталога. Автовозобновления нет.

После явного разрешения постоянного режима: оператор enable --permanent без
срока действия, но с generation и approval; установить один plist
~/Library/LaunchAgents/com.agency-w.kadrian-memory-sync.plist и bootstrap в gui/UID.
Не создавать второй агент. Установить только project-scoped Codex hooks путём
объединения с существующими hooks, без перезаписи чужих настроек. Проверить текущую
поддержку формата Codex перед установкой. До этой проверки не обещать совместимость
действующей версии приложения. Hook при закрытом канале честно сообщает неактуальность.

Контроль после реального выхода/входа в macOS: launchctl print одного label,
новое checked_at, версия облачной проекции, локальная правка и одно облачное событие,
восстановление сети, отсутствие дублей. Не перезагружать Mac без согласования.
Синтетический новый процесс и plutil -lint НЕ заменяют настоящий вход в macOS.

## Как остановить и откатить

1. На Mac agent_memory_run.py --config <существующий config> --stop создаёт STOPPED
   атомарно и не удаляет ни одного события. Затем bootout только данного launchd label;
   закрыть его project-scoped hooks. Уже идущую отправку останавливает серверный gate.
2. Оператор генерирует stop SQL с точной привязкой и выполняет его. Подтвердить
   enabled=false, новое поколение, отказ подписанного запроса. При таймауте закрыть
   Edge Function известной 503-заглушкой; не объявлять stop успешным до проверки.
3. При откате кода оставить gate закрытым и вернуть 503-заглушку. Не возвращать старый
   env-enabled обработчик, не откатывать общую БД и не удалять 38 ревизий/новые события.
   Служебную таблицу можно оставить disabled. Исходные копии и ключ Keychain сохраняются.

Новых платных сервисов нет. На каждый обмен добавляются проверки DB-выключателя;
это расход существующего Supabase, не новый сервер. Фактическую квоту/счёт проверить
перед постоянным включением, гарантий нулевого счёта сверх включённых квот нет.
