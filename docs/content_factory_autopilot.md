# Контент-завод: развёртывание автопилота

Автопилот добавляется в существующее приложение Агентства W. Каждый партнёр
создаёт свой проект, подключает свои аккаунты и включает публикацию по расписанию.
Ручной редактор постов, каруселей, Reels и ИИ-диалогов остаётся доступен.

Этот комплект подготовлен для проверки и развёртывания. Миграция в рабочем
Supabase, развёртывание Render, подключения живых аккаунтов и реальная публикация
пока не выполнялись. Прохождение офлайн-тестов не подтверждает доступ приложений
Meta или права конкретного сообщества ВК.

## Состав

| Компонент | Размещение | Назначение |
|---|---|---|
| Существующий `streamlit_app.py` | Текущее приложение Streamlit | Кабинет партнёра, настройки проекта, подключение площадок, календарь и материалы |
| `content_factory_setup.sql` | Тот же проект Supabase, что у Агентства W | Проекты, зашифрованные подключения, очередь, лимиты и приватные медиа |
| `content_factory_worker.py` | Отдельный Render Background Worker | Генерация и отправка без открытого браузера |
| `content_factory_oauth.py` | Отдельный Render Web Service | Вход через Instagram и Threads и сохранение подключения владельца |

Два сервиса Render используют один Dockerfile и разные команды запуска.
Они читают ту же базу и используют тот же ключ шифрования, что и Streamlit.
Локальный SQLite предназначен для разработки; независимые серверы в production
должны использовать общий Supabase. Постоянный диск Render для этого не требуется.

## 1. Подготовить Supabase

В SQL Editor существующего проекта Supabase выполните весь файл
[`content_factory_setup.sql`](../content_factory_setup.sql).
Он создаёт таблицы, серверные функции атомарного получения задания и резервирования
дневного лимита, а также приватный bucket `content-factory-media` с лимитом файла
100 МиБ. Повторное выполнение предусмотрено миграцией.

Проверьте, что bucket остаётся **Private**. Worker выдаёт временные подписанные
HTTPS-адреса непосредственно перед передачей медиа соцсети. Постоянно открывать
все черновики не требуется. Доступ к таблицам и функциям предоставляется серверной
роли `service_role`; ключ не должен передаваться браузеру или в код публикации.

## 2. Подготовить стабильные ключи и настройки

Используйте уже действующие `SUPABASE_URL` и серверный `SUPABASE_SECRET_KEY`
Агентства W. Для текущего REST-клиента подходит серверный ключ `service_role`
этого проекта; ключ `anon` не заменяет его.

Создайте **один раз**, в доверенном менеджере секретов:

- `CONTENT_FACTORY_FERNET_KEY`: действительный Fernet-ключ — 32 случайных байта,
  закодированных URL-safe Base64. Одно и то же исходное значение должно быть у
  Streamlit, worker и OAuth-сервиса.
- `CONTENT_FACTORY_OAUTH_SIGNING_KEY`: случайный секрет длиной минимум 32 байта.
  Одно значение используется Streamlit и OAuth-сервисом для привязки подключения
  к вошедшему партнёру и выбранному проекту.

При подключении к существующей установке можно оставить общий `FERNET_KEY`:
он используется, если отдельный `CONTENT_FACTORY_FERNET_KEY` не задан.
Если отдельный ключ подписи не задан, кабинет и OAuth-сервис подписывают вход
одинаковым серверным `SUPABASE_SECRET_KEY`. Значения на обеих сторонах должны
совпадать; новый отдельный ключ не следует вводить только на одной стороне.

Сохраните ключи в защищённых настройках и резервной копии менеджера секретов.
Не генерируйте новые значения при каждом запуске или развёртывании: уже сохранённые
подключения зашифрованы предыдущим ключом. Существующий `FERNET_KEY`, используемый
другими функциями Агентства, заменять не нужно. Значение
`CONTENT_FACTORY_FERNET_KEY` является настоящим локальным ключом, а не подстановкой
сетевого proxy.

| Настройка | Streamlit | Worker | OAuth-сервис |
|---|:---:|:---:|:---:|
| `SUPABASE_URL`, `SUPABASE_SECRET_KEY` | ✓ | ✓ | ✓ |
| `CONTENT_FACTORY_FERNET_KEY` | ✓ | ✓ | ✓ |
| `CONTENT_FACTORY_OAUTH_SIGNING_KEY` | ✓ | — | ✓ |
| `CONTENT_FACTORY_SERVICE_URL` | ✓ | — | ✓ |
| `CONTENT_FACTORY_RETURN_URL` | — | — | ✓ |
| `OPENAI_API_KEY` | ✓ для создания из кабинета | ✓ | — |
| `INSTAGRAM_APP_ID`, `INSTAGRAM_APP_SECRET` | — | — | ✓ |
| `THREADS_APP_ID`, `THREADS_APP_SECRET` | — | — | ✓ |

В Streamlit добавляйте новые настройки в Secrets как **корневые TOML-поля**,
до первой секции `[auth]` или другой таблицы. Существующие авторизацию, ключи и
прочие настройки сохраняйте. На Render вводите значения в защищённых переменных
Environment. Blueprint содержит `sync: false`, а не значения секретов.
Производственный `OPENAI_API_KEY` вводится в настройках сервера; это не требование
к зарезервированной переменной облачной среды Codex.

## 3. Развернуть сервисы Render

### Использовать уже работающий Instagram webhook

Если `instagram_webhook:app` уже работает, дополнительный Web Service не нужен.
Он обслуживает также `/connect/{platform}` и `/oauth/{platform}/callback`,
когда в его Environment заданы `CONTENT_FACTORY_SERVICE_URL`, `SUPABASE_URL`
и `SUPABASE_SECRET_KEY`. Существующие webhook, страницы и вход Instagram
продолжают работать по прежним адресам. Без настроек новые маршруты отключены.

Укажите в `CONTENT_FACTORY_SERVICE_URL` реальный HTTPS-origin этого сервиса,
без пути. В кабинете используется тот же origin из существующей настройки
`INSTAGRAM_OAUTH_SERVICE_URL`, если отдельный `CONTENT_FACTORY_SERVICE_URL`
не задан. Ключи базы, шифрования и подписи должны совпадать с кабинетом.
Команда существующего webhook-сервиса должна отключать access log, чтобы
одноразовые параметры входа не попадали в журналы:

```sh
uvicorn instagram_webhook:app --host 0.0.0.0 --port $PORT --no-access-log
```

Для фоновой обработки используйте отдельный Docker worker по файлу
[`deploy/content-factory/render-worker.yaml`](../deploy/content-factory/render-worker.yaml).
Этот вариант создаёт только один новый платный сервис. До подтверждения
проверьте актуальную стоимость тарифа в Render. Не добавляйте генерацию видео
в работающий цикл Неоны: она обрабатывается отдельно.

Приложения Meta всё равно должны разрешать новые Redirect URI, указанные ниже.
Существующее приложение Instagram можно использовать, если оно имеет
разрешение `instagram_business_content_publish`. Для Threads нужны его
собственные App ID и App Secret; отсутствие этих настроек не мешает Instagram.

### Отдельный сервис подключения

В Render создайте Blueprint из нужного GitHub-репозитория и ветки. Укажите
**Blueprint Path** `deploy/content-factory/render.yaml`. **Root Directory**
оставьте пустым: `dockerfilePath` и `dockerContext` в blueprint отсчитываются от
корня репозитория. `dockerContext` — `.`, Dockerfile —
`./deploy/content-factory/Dockerfile`.

Blueprint создаёт Web Service `agency-w-content-connect` и Background Worker
`agency-w-content-worker` на тарифе Starter в регионе Frankfurt. Оба тарифа
платные; стоимость хостинга и использование OpenAI учитываются отдельно.
Образ Python 3.12 устанавливает FFmpeg, DejaVu и сертификаты, затем зависимости
из `requirements_content_factory.txt`. Команды запуска:

```sh
python content_factory_worker.py --interval 60 --max-jobs 2
```

```sh
sh -c 'uvicorn content_factory_oauth:runtime_app --factory --host 0.0.0.0 --port "$PORT" --no-access-log'
```

OAuth-сервис запускается в одном экземпляре и одном Uvicorn-процессе.
Access log отключён, поскольку callback получает одноразовые параметры OAuth.
Health Check Path — `/health`; ожидается HTTP 200 с `{"status":"ok"}`.
Это подтверждает запуск HTTP-сервиса, но не права соцсетей и не обработку очереди.

После создания Render назначит реальный публичный HTTPS-адрес Web Service.
Введите **этот адрес без пути и query string** в `CONTENT_FACTORY_SERVICE_URL`
на Web Service и в Secrets Streamlit. Не выводите адрес из желаемого имени сервиса:
имя на Render может получить суффикс. `CONTENT_FACTORY_RETURN_URL` по умолчанию —
`https://agency-w.streamlit.app/`; при другом адресе кабинета обновите его.
После изменения переменных перезапустите соответствующие сервисы.

Оставьте одинаковые ключи Supabase и шифрования в обоих Render-сервисах и Streamlit.
Если доступ к OpenAI ограничен моделью или бюджетом, настройте поддерживаемые вашим
аккаунтом `CONTENT_FACTORY_TEXT_MODEL`, `CONTENT_FACTORY_IMAGE_MODEL`,
`CONTENT_FACTORY_SPEECH_MODEL` и `CONTENT_FACTORY_VOICE` в worker и, при необходимости,
Streamlit. Blueprint задаёт `gpt-5`, `gpt-image-2.5-sunburst`, `gpt-4o-mini-tts`, `alloy`
и качество изображения `high`. Поддерживаемые качества: `low`, `medium`, `high`,
`auto`. Рабочий доступ к этим моделям нужно подтвердить на реальном аккаунте.

## 4. Настроить вход через Instagram и Threads

В Meta Developers подготовьте приложения для Instagram Login и Threads,
принадлежащие оператору Агентства. App ID и App Secret вводятся только в
Environment OAuth-сервиса. В настройках приложений зарегистрируйте точные
Redirect URI, заменив `PUBLIC_SERVICE_ORIGIN` реальным HTTPS-origin сервиса:

```text
PUBLIC_SERVICE_ORIGIN/oauth/instagram/callback
PUBLIC_SERVICE_ORIGIN/oauth/threads/callback
```

Для Instagram нужны `instagram_business_basic` и
`instagram_business_content_publish`; для Threads — `threads_basic` и
`threads_content_publish`. Настройте разрешённые домены и redirect URI приложений,
необходимые страницу конфиденциальности и удаление данных. Для чужих аккаунтов
потребуются разрешения и статус приложения, которые Meta допускает для production;
режим разработки сам по себе не открывает публикацию для всех партнёров.
Используйте профессиональный Instagram-аккаунт с правом публикации.

Партнёр начинает подключение из **своего вошедшего кабинета**, в выбранном проекте,
через кнопку «Подключить Instagram» или «Подключить Threads». Короткоживущая ссылка
передаёт подписанную привязку владельца и проекта; приложение затем проверяет
OAuth-state и браузерную cookie. Обычный вход Telegram в Агентство W не выдаёт
разрешение на публикацию в Instagram или Threads.

## 5. Подключить ВК

Администратор сообщества вводит во вкладке «Площадки» положительный ID сообщества
и действующий ключ с правами на записи, фото и видео. Секрет вводится в поле
пароля и сохраняется в зашифрованном подключении выбранного проекта.
Фактическую совместимость ключа и права необходимо проверить на целевом сообществе.

Посты, карусели из фото и видео публикуются **на стене сообщества ВК**.
Размещение вертикального видео на стене не означает отдельную публикацию в ленте
VK Clips; этот маршрут в данном адаптере не реализован.

## 6. Настроить первый проект и выполнить приёмку

В **«Контент → Автопилот: контент и публикации»** создайте проект: продукт, аудитория, язык, голос бренда,
цель, CTA и цвет оформления. Выберите площадки, форматы, часовой пояс и слоты.
Один слот создаёт материал для каждой выбранной площадки; форматы чередуются.
Профили и медиа разных партнёров разделяются владельцем и проектом.

Подключите аккаунты во вкладке «Площадки». Для первой приёмки можно включить
«Проверять каждый материал перед публикацией», сохранить проект и нажать
«Заполнить контент-план». При этом ИИ создаёт материалы, но ждёт утверждения.
После приёмки снимите эту настройку и включите **«Включить автопилот»** — тогда
генерация и публикация идут без утверждения каждого материала. Worker должен
работать постоянно; открытая вкладка Streamlit его не заменяет.

Проверяйте результаты в «Материалах» и на самих площадках: готовые изображения,
порядок карусели, весь текст, озвучку и субтитры, идентификатор публикации и её
фактическое появление в правильном аккаунте. Отдельно проверьте паузу,
отключение аккаунта и сохранность материалов после перезапуска сервисов.

Дневной лимит ограничивает **попытки создания материалов**, а не точную сумму списаний.
Одна карусель создаёт 3–6 изображений; пост — одно изображение, видео —
четыре изображения и TTS-озвучку. Проверки автора, редактора и визуального редактора
также используют платный API. Разрешена одна осмысленная переработка текста и
не более одной коррекции изображения на весь материал. Подписка ChatGPT и
оплата Render не включают эти API-расходы. Неопределённый результат запроса не вызывает
автоматическое повторное списание. При «Проверяется результат отправки» сначала
сверьте сам аккаунт: нельзя считать таймаут доказательством отсутствия публикации.
Обход дневного лимита или безусловная повторная отправка не требуются.

Генерируемое автопилотом видео — вертикальный MP4 1080×1920 из четырёх
отдельных ИИ-сцен, с движением кадра, синтезированной речью и субтитрами.
Подписи распределяются по длительности речи, а не по распознанным временным меткам
каждого слова. Это не генерация нескольких кинематографических сцен. Старые
ручные режимы HeyGen/Runway и ИИ-диалогов сохраняются отдельно.

### Создание по задаче внутри завода

После выбора проекта заполните блок **«Что создаём?»**: задача обычными словами,
формат и подключённые площадки. Кнопка «Создать материал» сохраняет задание в
очереди. Постоянный worker подхватывает его даже при выключенном расписании;
в этом случае результат ждёт проверки. Повторная отправка того же задания
не создаёт дубликаты. Смена задания или кнопка переработки создают отдельную версию.

В проекте можно сохранить подтверждённые факты, примеры хороших текстов,
визуальный стиль и ограничения. Автор получает этот контекст при каждой генерации.
Корректор отдельно проверяет грамматику и естественность формулировок, затем
Стагирит проверяет содержание. При замечаниях автор дорабатывает текст один раз;
исправленный вариант снова проходит корректуру и проверку. Отклонённый текст
не запускает медиа.
Арт-директор разрабатывает конкретные сцены и единый стиль; каждая созданная
иллюстрация проходит отдельную визуальную проверку перед оформлением.

Текущий этап и отчёт проверки видны во вкладке «Материалы». Кнопка
«Обновить материалы» перечитывает очередь и счётчики без повторного создания.
В готовом или неудачном материале с сохранённым текстом задайте пожелания в поле
«Что изменить в тексте или оформлении?» и нажмите «Переработать материал».
Новая версия проходит полный цикл и требует проверки владельца. Исходная
версия сохраняется. Незавершённый или отклонённый материал нельзя утвердить
или отправить напрямую через повтор публикации.

Для автоматических публикаций подключите площадки и сохраните выбранное
расписание с включённым автопилотом. Проверка владельца регулируется отдельной
настройкой проекта. Эти правила не отменяют техническую и редакторскую проверки.

## Проверки разработчика

Из корня репозитория, в изолированном Python 3.12 с FFmpeg, ffprobe и Node:

```sh
python -m pip install -r requirements.txt -r requirements_worker.txt -r requirements_content_factory.txt opencv-python-headless==4.12.0.88
python -m unittest discover -s tests -v
```

Тесты используют подменённые сетевые ответы и не создают платные AI-задания и
публичные публикации. Проверка видео действительно запускает FFmpeg.
Для проверки сборки без развёртывания, из корня репозитория:

```sh
docker build -f deploy/content-factory/Dockerfile -t agency-w-content-factory .
```

Сам Blueprint и Docker-образ ещё не развёрнуты и не проверены на Render.
Перед production-приёмкой остаются фактическая миграция, запуск двух сервисов,
доступ к моделям, одобрение приложений и проверка публикаций на подключённых
аккаунтах. Эти операции выполняются после настройки реальных защищённых значений.
