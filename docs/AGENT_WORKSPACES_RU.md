## Файлы каждой новой папки

- AGENTS.md задаёт порядок работы Codex в открытом пространстве.
- Agent.md указывает роль и существующие профессиональные первоисточники.
- context/PROJECT.md, DECISIONS.md, FEEDBACK.md, CHECKS.md задают контекст,
  историю решений, обратную связь и проверки.
- tasks/README.md объясняет сохранение снимка задания через Memory.prepare_task.
- knowledge/SOURCES.md содержит ссылки на оригиналы.
- results/README.md объясняет хранение исхода в существующем Repository.

tools/prepare_agent_workspaces.py создаёт только отсутствующие файлы. Существующие
документы сохраняются побайтно. Локальные папки и клиентские материалы следует
держать вне публичного checkout. В публичном PR находятся генератор, адаптер,
тесты и эта карта; частные локальные файлы туда не входят.

## Чтение и обучение

AgentWorkspace.begin сначала проверяет текущий доступ TeamMemory, фиксирует
точную привязку локальной папки к роли, владельцу и canonical project UUID,
читает свои локальные материалы и первоисточники, затем сохраняет снимок
задания и хеш материалов через существующий Memory.prepare_task.

Для следующего задания загружаются собственные доказательства исправлений
и удачных решений. Требуется проверка доверенного владельца/проверяющего,
passed=true и совпадающий хеш текста. Последующая отрицательная проверка
отменяет применение опыта. Предложенные общие правила остаются вне контекста
утверждённых правил до существующего owner-approval.

AgentWorkspace.finish сохраняет дату, область из Binding, задачу, ожидание,
результат, оценку, источник, причину и её достоверность, исправление, проверку
и следующее применение. Стабильный event_id использует идемпотентность Memory.

Инструкции в AGENTS.md применяются при работе Codex в соответствующей папке.
Они дополняют проверку доступа в адаптере. Отдельной системной песочницы для
произвольных инструментов Codex этот код не создаёт. Серверная изоляция
подготовленного пути проверяется адаптером и привязкой папки; существующие
права файловой системы и инструментов остаются самостоятельной границей.

## Приёмка Разведчика

run_competitor_research получил необязательный experience_workspace и task_id.
По умолчанию workspace отсутствует, существующий вызов интерфейса продолжает
свой прежний путь. Подготовленный путь сначала читает материалы и проверенный
опыт, добавляет их в действующий запрос Разведчика и записывает исход.
Проверенные правила сохраняют свой отдельный статус. Созданный отчёт получает
оценку unknown до проверки качества.

Синтетический тест фиксирует ошибку классификации рекламного заявления,
сохраняет исправление, подтверждает его владельцем и запускает следующее
задание через реальную функцию Разведчика. Подставной provider проверяет, что
исправление реально включено в запрос, и возвращает скорректированный отчёт.
Это доказывает путь передачи контекста и сохранение результата. Качество ответа
живой модели после подключения требует самостоятельной приёмки.

Сохранённый результат того же task_id возвращается без второго обращения
к provider. Ошибка provider сохраняется по типу исключения, без его частного
текста. Свежий процесс Python повторно читает проверенный опыт из того же
тестового Repository. Проверяются также соседняя роль, другой проект,
отзыв доступа, неподтверждённое исправление, повторные события и symlink.

## Условия подключения рабочих агентов

Нужно согласовать пилотного владельца/проект, приватное расположение рабочих
материалов, серверный access_check и состав сохраняемых данных. Кадриан
использует свой существующий контур. Привязка остальных runtime пока готовится.
Новых grants, hooks, cron, межагентной синхронизации или production-настроек
этот этап не устанавливает. Схема БД и авторские документы остаются исходными.
Интервал подготовки встречи1ч/2ч остаётся решением директора.

Проверки выполняются с синтетическими данными. Живые модели, платные
исследования и отправка Telegram в этом этапе не вызываются.
