# Отдельные фильмы Кадриана — исправление видеостудии

Подготовлено отдельно от PR №85. Основа: main `2ae3af661a0c5cae062bdd08d94b39f07f5dbd58`.
Ветка: `codex/kadrian-film-sessions`. Установка владельцем ещё не разрешена.

## Как это будет работать после утверждения и установки

1. Откройте Кадриана и выберите проект.
2. Нажмите **🎬 Новый фильм / мультфильм**. Старый фильм останется в списке
   **Сохранённые фильмы**, новый начнётся с пустой переписки, сценария и вложений.
3. При желании задайте название и нажмите «Сохранить название».
4. Обсуждайте и редактируйте выбранный фильм. Прикрепляйте материалы именно к нему.
5. Для продолжения другого фильма выберите его в списке. Переключение не запускает
   производство. Адрес страницы содержит идентификатор выбранного фильма; доступ
   по-прежнему требует входа владельца и доступа к его проекту.
6. Текущий статус берётся из сохранённых заданий, обновляется каждые 30 секунд
   при открытой странице. Старые сообщения — история, а не индикатор работы.
   При недоступности хранилища интерфейс сообщает, что статус не получен.

Старые задания без идентификатора фильма остаются в «Фильм 1 (прежняя история)».
Существовавшие до этого исправления фильмы нельзя автоматически надёжно разделить:
они сохранены вместе с прежней историей, без выдуманного распределения по фильмам.
Новые фильмы разделяются с момента создания. Перенос чужих материалов между фильмами
не выполняется; отдельного интерфейса разрешённого импорта в этом исправлении нет.

## Хранение и защита

- `kadrian_films` в существующем JSON проекта: версия, UUID прежнего фильма,
  каталог фильмов с UUID, названием, временем создания, перепиской, сценариями,
  текущими вложениями, историей замены вложений и настройками формата.
- Каждая новая реплика сохраняет сценарий и идентификатор запроса этой версии.
  Прежние реплики и файлы не удаляются. Старое поле `kadrian_chat` сохраняется;
  изменения прежнего фильма также отражаются там для совместимости с откатом.
- Файлы остаются в существующем частном хранилище. В JSON сохраняются ссылки и
  контрольные суммы, а не большие файлы. Новые загрузки получают пространство UUID
  фильма; задания содержат `film_id`. Имена оригинальных загрузок сохраняются.
- `FilmStore` проверяет владельца, проект, фильм, ссылки на файлы и задания;
  фильтрация по фильму выполняется в базе **до** ограничения размера выдачи.
- Записи проекта объединяются через существующую оптимистическую блокировку
  `updated_at`. Конфликт перечитывает актуальную версию, сохраняя другие фильмы
  и общие заметки. Неудачное сохранение ответа блокирует навигацию до повтора.
- Общие правила, проектные факты и `kadrian_notes` остаются общими. Код не меняет
  общие инструкции и не включает новую систему памяти из PR №85.
- Кнопка нового фильма и переключение не меняют задания, их состояние, номера
  поставщика, контрольные точки или оплату. Фоновый worker продолжает прежние
  задания независимо от открытого фильма и браузера. Выполненные задания не
  ставятся заново в очередь. Ключи защиты от повторов разделены по фильмам.
- Фильмы не создают отдельные учётные записи или права между соавторами одного
  владельца: единицей доступа остаётся существующий владелец/проект.

## Затронутые файлы

- `kadrian_films.py`: жизненный цикл фильмов, граница доступа, сохранение вложений.
- `kadrian_studio_ui.py`: кнопка, список, чистый чат, восстановление, название,
  раздельные ключи элементов интерфейса и сохранение файлов перед производством.
- `kadrian_memory.py`: сохранение сценария каждой новой реплики, без изменения правил.
- `kadrian_actions.py`: статус по состоянию задания; при постановке — «Задание в очереди».
- `kadrian_production_ui.py`: статус всех последних заказов выбранного фильма,
  собственные библиотеки и монтаж через ограниченное хранилище.
- `content_studio_music_ui.py`: пространство интерфейса музыки отдельно для фильма;
  вызовы вне видеостудии сохраняют прежние ключи.
- `content_factory_store.py`: чтение заданий одного фильма для SQLite/Supabase,
  поддержка уже разрешённых в чате OGG/MOV/WebM при сохранении вложений.
- `tests/test_kadrian_films.py`: автономные проверки жизненного цикла и интерфейса.

SQL-миграции, новые таблицы, ключи, новые службы и фоновые процессы не нужны.
Этот PR сам по себе не устраняет другие ранее обнаруженные недостатки производства:
точечную замену сцен и ограничения планировщика речи нужно исправлять отдельно.

## Проверка

```sh
python -m unittest tests.test_kadrian_films -v
python -m unittest discover -s tests -p 'test_kadrian*.py' -v
python -m unittest discover -s tests -v
```

Новые проверки создают только временную SQLite и файлы тестов. Проверены три
последовательных фильма, перезапуск хранилища и нового окна Streamlit AppTest,
возврат к истории, общие правила, раздельные сценарии и вложения, конфликт записи,
потеря подтверждения записи, защита от повторного создания, изоляция владельцев и
проектов, музыка/монтаж/HeyGen/Runway, сохранённые оплаченные задания и получение
результата ранее оплаченной задачи без нового заказа. Контракт запросов Supabase
проверяется подменой HTTP-слоя; рабочая Supabase не используется.

## Резервирование и откат после будущей установки

Перед установкой оператор должен сохранить обычную защищённую резервную копию
проектов, заданий и объектов хранилища средствами существующей инфраструктуры.
В этой задаче рабочие данные не читаются и резервная копия production не создаётся.

Для отката вернуть предыдущую версию приложения, **не удалять** `kadrian_films`,
`film_id` или файлы. Старый интерфейс увидит прежний фильм через `kadrian_chat`;
новые останутся в JSON и станут доступны после возврата исправления. Старый код
не предоставляет интерфейса для новых фильмов. После отката не запускать новые
заказы до проверки оператором: старый интерфейс фильтрует библиотеку по проекту,
а не по фильму. Повторная установка восстанавливает разделение без конвертации
заданий. Не нужно отменять или повторно оплачивать уже принятые задания.

## Оплата и ограничения

Новых платных сервисов и платных проверочных генераций нет. Хранение использует
существующий объём базы и файлового хранилища; его рост подчиняется текущему тарифу.
Создание настоящих видео после установки продолжит оплачиваться по тарифам
подключённых поставщиков. Этот PR не обещает бесплатное видеопроизводство.

Каталог фильмов хранится в JSON проекта с CAS всей записи: для нынешнего объёма
это обходится без миграции; при очень большой истории понадобится отдельная
постраничная структура. Библиотеки показывают до 100 последних заданий фильма,
карточки статусов — до 30; записи сверх выдачи не удаляются.
