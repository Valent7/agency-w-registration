# Постоянная память: автоматический обмен Mac ↔ Агентство W

Состояние: реализация в отдельной ветке, испытания на искусственных данных. Не установлено на рабочий Mac/сервер; прежняя ручная синхронизация PR №85 сохраняется. Этот документ не является разрешением на установку.

## Поведение после утверждённой установки

- Вход пользователя в macOS запускает пользовательский LaunchAgent. До входа пользователя, при выключенном/спящем Mac и заблокированной Связке ключей локальный обмен не выполняется. После входа/пробуждения ближайший цикл догоняет облако.
- RunAtLoad, StartInterval=60 секунд и WatchPaths трёх файлов запускают проверку независимо от открытия Codex. launchd объединяет частые запуски; это не обещание передачи каждого нажатия клавиши.
- SessionStart и UserPromptSubmit в проектных Codex hooks выполняют проверку облачной версии перед работой. В текущей версии Codex совместимость hooks требует приёмочной проверки после установки. При недоступности связи агент получает предупреждение, может работать с локальной копией, но не должен утверждать, что память актуальна.
- Изменения context/PROJECT.md, context/DECISIONS.md и context/FEEDBACK.md сначала атомарно записываются в зашифрованную очередь, затем передаются. При дописывании передаётся добавленный текст с хешами исходного и нового файла; при редактировании середины — новый снимок файла.
- Облачные записи возвращаются в context/SYNCED_MEMORY.md штатным механизмом проекции PR №85. Они НЕ перезаписывают исходные локальные журналы. Это двусторонний обмен знаниями, а не побайтовое зеркалирование одних и тех же файлов.
- Agent.md, AGENTS.md и общие инструкции автоматически не передаются и не меняются. Уже утверждённые облачные правила владельца и этого агента доступны как контекст: сервер передаёт только allowlist полей утверждённых правил, без общих заметок/клиентских фактов/проверочных свидетельств. Их версии проверяются отдельно от версии проекта. Новые локальные тексты записываются как legacy/unknown: слово «проверено» в файле не является серверным доказательством и не утверждает правило.
- При выключенном Mac облачная память продолжает работать в существующем приложении. Агент синхронизации ничего не запускает в видеопроизводстве, не трогает очередь роликов и не возобновляет worker.

## Одна система памяти

Единственное авторитетное хранилище знаний — существующие agent_memory_workspaces/revisions, Repository и Memory PR №85 в Supabase. Новых таблиц, индексов знаний, векторной базы и платных сервисов нет. На Mac transport.enc — только транспортная очередь/номера событий/хеши/контрольный текст для вычисления добавленных фрагментов. Она не заменяет память и не является второй базой знаний. Подтверждённые события сохраняются в неизменяемой облачной истории; обычные отправленные пакеты удаляются из транспортной очереди.

## Доступ и клиентские данные

У каждого Mac/агента/проекта отдельная регистрация device_id → публичный Ed25519-ключ + точная область owner/agent/workspace/project. Сервер получает идентичность из доверенной регистрации, а не из JSON клиента. Проверяются подпись, срок запроса и флаг выбранного пилота. Операции только pull/push. Нет approve, restore, SQL, генераций и доступа к другому проекту. Повтор подписанного push безопасен благодаря стабильному событию и CAS.

Приватный ключ создаётся только на этапе явной установки и хранится в macOS Keychain, с доступностью WhenUnlockedThisDeviceOnly. В plist, аргументах процесса, Git и логах приватных ключей нет. База Supabase и её service-role ключ остаются на сервере. Для очереди/конфликтных копий используется Fernet с отдельным ключом, полученным из устройства; файлы 0600, каталоги 0700. Проекция, исходные журналы и старые резервные копии содержат текст — защищать учётной записью Mac и FileVault; этот код не включает FileVault сам.

HTTPS обязателен, редиректы и автоматическое использование proxy/.netrc отключены. Только три allowlist-файла; clients/, видео, вложения, env и каталоги Codex не сканируются. Детектор известных секретов дополнительно останавливает передачу, но не заменяет правило «не записывать секреты в журналы». Открытый endpoint ограничивает размер запроса; ошибки не возвращают содержимое/ключи. Маршрут отсутствует по умолчанию, флаг AGENCY_MEMORY_DEVICE_SYNC выключен.

## Конфликты, сбои, повторы

Событие имеет device_id, монотонный номер, base_revision и event_id. Перед отправкой оно сохраняется с fsync. При потере ответа повтор возвращает уже сохранённое событие; тот же номер с другим содержимым отклоняется. CAS-гонка перечитывает актуальный документ, сохраняя чужие записи. При несовпадении базовой версии обе записи остаются в облаке; зашифрованный конфликтный пакет сохраняется на Mac. Семантического слияния и выбора победителя нет.

Проекция заменяется атомарно с хеш-проверкой и резервной копией; её ручное изменение не теряется. Два процесса сериализуются flock. Повреждённая очередь не сбрасывается; потерянное состояние устройства не создаётся заново автоматически (это могло бы повторить номера). Восстановить резервную копию вместе с доступным исходным ключом либо зарегистрировать новое устройство; непереданные пакеты сохранить для контролируемого восстановления. DeviceOnly-ключ нельзя считать переносимой резервной копией для нового Mac.

Сетевые/авторизационные ошибки оставляют очередь и прежнюю проекцию. Повтор — при следующем запуске launchd, максимум 20 пакетов за цикл. Часы Mac должны быть корректными (окно подписи 5 минут). В status.json только статус, число пакетов, последняя облачная версия/время сверки. Предупреждение hook не подменяется зелёным статусом.

Лимит существующего документа PR №85 — 2 MB. Новые фрагменты экономят место, но бесконечную вместимость это не создаёт. При достижении лимита передача останавливается с сохранением очереди; автоматического удаления старой памяти нет. Архивация/компактация потребует отдельного проекта и утверждения.

## Установка специалистом после отдельного разрешения

1. Проверить draft PR/CI и согласовать включение маршрута на существующем ASGI-сервисе публикации (content_factory_oauth.runtime_app или его существующее подключение в instagram_webhook). Работающий Streamlit не умеет принимать этот endpoint. Убедиться, что ASGI-сервис доступен и настроен; не создавать новый платный сервис автоматически. Память PR №85/выбранный проект должны быть включены на нём так же, как на web.
2. В постоянной локальной папке Application Support создать из проверенного коммита отдельный Python 3.12 runtime. Установить deploy/memory-sync/requirements-mac.txt. Достаточно agent_memory.py, agent_memory_sync.py, agent_memory_device.py, agent_memory_daemon.py, agent_memory_mac_keychain.py, agent_memory_mac_setup.py. Не использовать /tmp или изменяемую рабочую ветку как рабочий runtime LaunchAgent.
3. `agent_memory_mac_setup.py prepare` получает явные --root, --output, --python, --code, --owner, --project, --endpoint. Создаёт только config.json (без секретов), launch-agent.plist и codex-hooks.json в заданной папке. Повтор поверх готовой конфигурации запрещён; сначала сделать резервную копию/сверить изменения.
4. Проверить созданные scope, endpoint, абсолютные пути и plist. `enroll --config …` отдельно создаёт новый ключ устройства в Keychain и device-public-registration.json. Этот файл содержит только публичный ключ/область. API-ключи существующих провайдеров не меняются.
5. Добавить публичную регистрацию в AGENCY_MEMORY_SYNC_DEVICES существующего ASGI-сервиса, не затирая другие регистрации. Включить AGENCY_MEMORY_DEVICE_SYNC=1 и пилотные флаги выбранного проекта; развернуть только утверждённый код. Любые изменения production требуют отдельного разрешения владельца.
6. Запустить один --preflight и один обычный цикл, проверить статус/контрольные суммы/область. Только затем установить plist в ~/Library/LaunchAgents/com.agency-w.kadrian-memory-sync.plist и выполнить `launchctl bootstrap gui/$(id -u) …`. Пользовательский агент стартует при последующем входе без Codex.
7. С резервной копией текущего файла объединить подготовленные hooks с Kadrian/.codex/hooks.json, сохранив существующие обработчики. Не копировать поверх чужих hooks и не устанавливать глобально для всех клиентов. Это отдельный проверяемый шаг установки; код не изменяет инструкции автоматически.
8. Приёмка: новый локальный синтетический маркер → облачная версия → обратная проекция; отключение сети/включение, выход/вход в macOS, запуск Codex, заблокированный Keychain, отзыв устройства. Удаление тестовых записей из неизменяемой памяти не предусматривать: для приёмки использовать явные безопасные отметки либо тестовый проект.

## Откат

Выполнить launchctl bootout для этого Label и убрать только его plist; с резервной копией убрать только два добавленных hook-обработчика, сохранив прочие. Отозвать регистрацию устройства на сервере/выключить AGENCY_MEMORY_DEVICE_SYNC. Копию очереди/конфликтов/Keychain и облачную историю сохранить. Не удалять таблицы PR №85, не восстанавливать старую базу целиком, не трогать видео-worker. Старый контролируемый обмен PR №85 остаётся доступен.

## Источники проверенных механизмов

- Apple: https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html — пользовательские LaunchAgents запускаются после входа пользователя.
- OpenAI: https://learn.chatgpt.com/docs/hooks — проектные .codex/hooks.json, SessionStart/UserPromptSubmit и additionalContext. Реальный запуск hooks текущим экземпляром Codex проверяется только после согласованной установки.
- Supabase: https://supabase.com/docs/guides/api/securing-your-api — права и RLS. Новых разрешений Data API для Mac не добавляется.
