# Карта конкурентных преимуществ и развития Агентства W

**Версия:** 1.0  
**Дата:** 23 августа 2026  
**Назначение:** не копировать конкурентов, а видеть рынок, защищать сильные стороны Агентства W и забирать только те идеи, которые проходят миссию W.

---

## 1. Неподвижное ядро W

**Миссия:** Агентство W возвращает человеку время.

**Главный принцип:** Не человек обслуживает программу. Программа служит человеку.

**Роль человека:** человек остаётся Директором — ставит цели, принимает ключевые решения, строит отношения и создаёт своё настоящее.

**Фильтр любой новой идеи:**
1. Возвращает ли она человеку время?
2. Убирает ли лишнее ручное действие?
3. Улучшает ли реальный результат, а не просто добавляет функцию?
4. Помогает ли агентам работать как одной команде?
5. Остаётся ли человек Директором и сохраняет ключевые решения?

---

## 2. Главное конкурентное ядро Агентства W

Агентство W не должно соревноваться по количеству моделей, кнопок или ИИ-персонажей.

**Наша зона силы:**

> Человек ставит цель, а виртуальное Агентство организует реальную работу между специализированными ИИ-сотрудниками вокруг конкретных человеческих отношений и возвращает Директору только те решения, которые действительно требуют человека.

Базовый путь W:

**понять проект → найти подходящих людей → объяснить, почему они подходят → Директор выбирает → Неона начинает человеческий разговор → ведёт диалог → осознанная встреча → регистрация/решение → Неола помогает повторить путь → Стагирит видит результат всей цепочки.**

## 3. Что W уже делает особенно хорошо

| Сильная сторона W | Почему это важно | Защищать |
|---|---|---|
| Человек остаётся Директором | Автоматизация не отнимает контроль | Да, как часть Конституции |
| Стагирит координирует специалистов | Пользователю не нужно самому переносить работу между агентами | Да |
| Неония → Неона → встреча → Неола | Это не набор ИИ-инструментов, а бизнес-путь | Да |
| Человеческий контекст в диалоге Неоны | Разговор развивается из ответа кандидата, а не из жёсткого скрипта | Да |
| Уважение границ человека | Явное «не пишите» останавливает контакт; молчание не повод преследовать | Да |
| Telegram как реальная рабочая среда | Агентство работает там, где уже общаются люди | Да |
| Сопровождение после регистрации | W думает не только о привлечении, но и о воспроизводимости результата | Да |
| Ежедневная селекция Стагирита из подготовленного пула | Директор получает следующий практический шаг, а не просто аналитику | Да |
| Простая внешняя логика | Внутри может быть сложная система, но Директору нужен понятный результат | Да |

| Работа с моментом обращения | Clay, 11x, Artisan | W хорошо думает «кому», но ещё слабее «почему именно сейчас» | **P2** |

## 6. Что нужно создать в W

### 6.1. Единая «Память Агентства W» — P0

Не новый экран с сотней файлов, а внутренний слой общей правды.

Минимальные сущности:
- профиль Директора;
- проект и его ЦА;
- возможности W: что реально работает сейчас;
- утверждённые правила и Конституция;
- контакты и история отношений;
- выводы Неонии с доказательствами;
- история диалогов Неоны и причина текущего статуса;
- встречи и решения;
- структура партнёров;
- результаты работы агентов.

**Правило доступа:** каждый агент получает только тот контекст, который нужен его роли.

### 6.2. Карточка человека 2.0 — P0

Одна карточка должна отвечать за 10 секунд:

- кто этот человек;
- откуда контакт;
- знакомый или холодный;
- почему Неония считает его подходящим;
- какие факты это подтверждают;
- есть ли свежий сигнал;
- кто и когда ему писал;
- что он отвечал;
- было ли возражение;
- просил ли не писать;
- назначалась ли встреча;
- каков следующий допустимый шаг.

### 6.3. Неония: «доказательство перед рекомендацией» — P0

Для каждой рекомендации хранить:

**Факт → источник → дата → вывод → уверенность.**

Если данных нет:

> **Недостаточно данных.**

Отдельно оценивать:
- **Fit:** соответствует ли человек ЦА;
- **Timing:** есть ли основание считать, что разговор уместен именно сейчас.

Не использовать психодиагностику или выдуманный «портрет человека» вместо наблюдаемых данных.

### 6.4. Неона: контур обучения на реальных разговорах — P0

Неона уже получила базу возражений. Следующий уровень — научиться измерять не красоту ответа, а результат диалога.

Хранить для каждого разговора:

**первое сообщение → ответ → тип ответа → ответ Неоны → продолжил ли человек разговор → встреча / отказ / пауза / стоп.**

Из этого Стагирит со временем должен видеть, какие подходы реально работают.

### 6.5. Evals W — P0

Перед публикацией новой версии агента прогонять набор контрольных сценариев.

Пример для Неоны:
- сложный вопрос;
- «нет времени»;
- «у меня уже есть ИИ»;
- «мне это не нужно»;
- «не пишите мне»;
- интерес к встрече;
- запрос цены, которую Неона не знает;
- провокационный или не относящийся к теме вопрос.

Проверять:
- не выдумывает ли факт;
- понимает ли границу;
- не давит ли;
- сохраняет ли язык кандидата;
- использует ли один уместный аргумент;
- умеет ли передать вопрос Директору;
- ведёт ли к осознанной встрече при наличии интереса.

### 6.6. Уровни автономности — P1

**Уровень 1 — «Учимся вместе».**  
Все внешние ответы требуют утверждения Директора.

**Уровень 2 — «Работаем вместе».**  
Обычные ответы агент отправляет сам; нестандартные, финансовые, чувствительные — показывает Директору.

**Уровень 3 — «Доверенный сотрудник».**  
Агент самостоятельно ведёт обычную работу в пределах Конституции; ключевые решения эскалирует.

Разрешение должно назначаться **по действию**, а не просто «агент включён/выключен».

### 6.7. Версионирование агентов — P1

Каждый рабочий агент должен иметь:
- имя;
- номер версии;
- дату;
- список изменений;
- набор обязательных тестов;
- статус: draft / test / production;
- возможность отката.

Принцип:

> Улучшили Неону один раз — после успешных тестов обновление безопасно становится доступным всем кабинетам, а личные данные и настройки владельцев остаются отдельными.

### 6.8. Реальный фон — P1

Разделить два понятия:

**«Сформировано при открытии кабинета»** и **«выполнено системой в фоне в заданное время».**

Не называть фоновым то, что требует открытия Streamlit.

Будущие фоновые задачи:
- обновление пула Неонии;
- конкурентная разведка;
- подготовка утреннего брифа Стагирита;
- проверка свежих сигналов;
- технические проверки системы.

Внешнее сообщение человеку не должно автоматически становиться фоновой задачей без соответствующего разрешения Директора.

### 6.9. Коммерческая multi-tenant архитектура — P1

Каждый владелец кабинета имеет:
- свои Telegram/каналы;
- свои контакты;
- свои диалоги;
- свой календарь;
- свою структуру;
- свою память проекта;
- свои разрешения агентам.

Общие для всей W:
- код и ядро агентов;
- Конституция;
- безопасные обновления;
- стандарты качества;
- базовые инструменты.

**Данные разных владельцев никогда не смешиваются.**

### 6.10. Агент конкурентной разведки W — P1

Рабочая формула:

**найти → проверить → понять → сравнить → предупредить → научить.**

Для каждого факта конкурента хранить:

**конкурент → функция → официальный источник → дата проверки → почему важно → есть ли аналог в W → где W сильнее/слабее → проходит ли идея Тест миссии → рекомендация → кому передать.**

Адресаты:
- **Неоне** — факты для корректной работы с вопросами и сравнением конкурентов;
- **Стагириту** — идеи и угрозы для архитектуры;
- **Директору** — только существенные изменения и решения.

Не уведомлять о каждом маркетинговом посте конкурента.

## 7. Порядок развития: не строить всё одновременно

### Этап A — «Качество текущего W»
**Сейчас.**

1. Набрать реальные диалоги Неоны после обновления возражений.
2. Зафиксировать метрики цепочки: рекомендован → выбран → первое сообщение → ответ → содержательный диалог → встреча.
3. Создать минимальную Карточку человека 2.0.
4. Добавить Неонии доказательства и «недостаточно данных».
5. Создать первые Evals для Неоны.

**Почему первым:** без достоверных данных нельзя понять, что действительно улучшать.

### Этап B — «Агенты становятся одной командой»

1. Спроектировать Память Агентства W.
2. Убрать повторный сбор уже известных данных разными агентами.
3. Добавить уровни автономности.
4. Добавить полноценный журнал handoff: кто → кому → что передал → результат.
5. Подключить конкурентного Разведчика к Стагириту.

### Этап C — «Готовность к коммерческому масштабированию»

1. Версии агентов и автоматические контрольные тесты.
2. Multi-tenant изоляция кабинетов.
3. Централизованные безопасные обновления.
4. Настоящие фоновые задачи.
5. Mobile-first проверка ключевых маршрутов.
6. Интеграции только по реальной потребности пользователей.

## 8. Что W сознательно НЕ будет делать

Это тоже конкурентное преимущество.

| Не делаем | Почему |
|---|---|
| Не гонимся за количеством ИИ-моделей | Пользователь покупает результат и время, а не каталог моделей |
| Не превращаем Директора в инженера workflow | Техническая кухня должна быть скрыта |
| Не выдаём догадку ИИ за факт | Лучше «недостаточно данных» |
| Не преследуем человека после молчания | Отношения важнее показателя активности |
| Не продолжаем контакт после явной просьбы не писать | Граница человека важнее воронки |
| Не автоматизируем ключевые решения без разрешения | Человек остаётся Директором |
| Не копируем функцию только потому, что она есть у конкурента | Каждая идея проходит миссию W |
| Не добавляем интерфейс ради интерфейса | Новая функция должна уменьшать, а не увеличивать работу пользователя |

## 9. Пять стратегических показателей W

Вместо «сколько функций добавлено» измерять:

1. **Сколько времени Директору вернуло Агентство.**
2. **Доля рекомендаций Неонии, которые привели к содержательному ответу.**
3. **Доля диалогов Неоны, которые привели к осознанной встрече.**
4. **Сколько действий Агентство выполнило без лишнего ручного переноса информации между агентами.**
5. **Доля критичных действий, где контроль Директора сработал правильно.**

Дополнительно для качества: количество выдуманных фактов должно стремиться к нулю; явные просьбы «не писать» должны соблюдаться в 100% случаев.

## 10. Стратегический вывод версии 1.0

На рынке уже есть сильные отдельные решения:
- лучше W в общей CRM-памяти;
- лучше W в массовой веб-разведке и сигналах;
- лучше W в инфраструктуре multi-agent;
- лучше W в версионировании и масштабировании на множество аккаунтов.

Поэтому W не следует заявлять, что «конкурентов нет».

**Возможное устойчивое преимущество W — в другом:** связать специализированных агентов вокруг живого пути человека и проекта так, чтобы ИИ забирал рутину, агенты передавали работу друг другу, а Директор включался в момент человеческого решения.

Задача следующего этапа — превратить это преимущество из архитектурной идеи в измеримую систему: **общая память + доказательность + качество агентов + история отношений + безопасная автономность.**
